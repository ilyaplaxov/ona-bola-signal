# Сценарий демо и чекпоинта

Для репетиции 18 ноября и финала 19 ноября. Вместе с [`HANDOVER.md`](HANDOVER.md) написан по-русски, потому что это рабочие документы команды. Надписи на экране даны так, как они выглядят в интерфейсе (по-узбекски).

## 1. За 15 минут до показа

1. Docker Desktop запущен. Из папки `ona-bola-signal`:

   ```bash
   npm run db:up
   ```

   ```bash
   npm run e2e
   ```

   `npm run e2e` за 15 секунд проходит весь сценарий в Chrome, сбрасывает базу до и после и обновляет скриншоты в `docs/demo/`. Если он зелёный, демо работает.

2. Запустить приложение и открыть http://localhost:5173:

   ```bash
   npm run dev
   ```

3. Выбрать роль **Nilufar Saidova · Hamshira**, язык **UZ** (для русскоязычных менторов — **RU**). Закрыть лишние вкладки, масштаб браузера 110–125 % для проектора.
4. С ИИ или без:
   - **Без ИИ** (по умолчанию). Панели ИИ скрыты, всё остальное работает без интернета.
   - **С ИИ.** В `backend/.env` указать `AI_ENABLED=true` и `ANTHROPIC_API_KEY=...`, затем перезапустить `npm run dev`. Проверка: на карточке пациентки появились фиолетовая панель «Izohdan toʻldirish (AI)» и кнопка «AI izohi». Нужен интернет. Один пробный вызов до выхода на сцену.
5. Если `npm run e2e` не запускали, сбросить базу вручную: `npm run db:reset`.

## 3. Чекпоинт 18 ноября: три сессии по 10 минут

Каждая сессия: 2–3 минуты на суть, 3 минуты на демо по разделу 2, остальное — вопросы. Итог чекпоинта — среднее трёх сессий.

### Техническая

- **Архитектура:** React + TypeScript, Express + TypeScript, Postgres, общие Zod-контракты в `shared/`. Ответ API сверяется с контрактом, поэтому фронтенд и бэкенд не могут тихо разъехаться.
- **Risk Engine:** чистая функция `assess()`, без базы, сети и часов. Одинаковый вход даёт одинаковый результат и хэш входа. Версия набора правил сохраняется в каждой оценке.
- **Надёжность:** визит обрабатывается в одной транзакции; повтор того же `submissionId` возвращает первый результат; журнал аудита только дополняется и сохраняет порядок событий.
- **ИИ:** Claude только извлекает значения из заметки и объясняет оценку. Структурированный вывод по схеме; единицы пересчитываются в коде, а не моделью; без единицы значение не угадывается. Таймаут 15 с, при отказе включается запасная модель, при любой ошибке форма остаётся ручной. В схемах ответа нет поля зоны.
- **Тесты:** юнит- и интеграционные тесты бэкенда на настоящей тестовой базе, e2e в браузере (`npm run e2e`). Цифры — в `HANDOVER.md`, раздел 10.
- **Честно о пробелах:** нет настоящей авторизации (демо-заголовок роли); алерты опросом раз в 5 с, без push; правила не проверены врачом.

### Бизнес

- **Проблема** (цифры из `data-pack/README.md`, часть взята из СМИ, первоисточники проверить):
  - 879 599 живорождений в 2025 году;
  - материнская смертность 14,7 на 100 000 (2024);
  - 62,8 % материнских смертей 2025 года признаны предотвратимыми. Мониторинг групп риска бьёт именно сюда.
- **Пользователи:** медсестра и врач районной поликлиники; специалист-получатель алертов (OvaBMU, как в постановке задачи; расшифровку не даём, пока её не подтвердит ментор); руководитель смотрит дашборд.
- **Почему сейчас:** реформа первичного звена. Медицинские бригады с прикреплённым населением работают во всех районах с 1 января 2026 года (УП-88). Бригадам нужен инструмент учёта своей группы риска.
- **Путь:** пилот в одном районе → интеграция с национальными системами → уведомления в Telegram и эскалация по сроку (roadmap) → новорождённые (задачи № 10 и № 11).

### Доменная

- **Источники:** национальные клинические протоколы МЗ РУз, приказ № 180 от 23.06.2025: антенатальный уход и ведение беременных с ЖДА. PDF лежат в `data-pack/`, страницы указаны у каждого правила (`RULES_PROVENANCE.md`, страница **Qoidalar**).
- **Статус:** пороги взяты из протоколов, но какую зону даёт правило, выбрала команда. Поэтому все правила ILLUSTRATIVE.
- **Вопросы ментору:** [`MENTOR_QUESTIONS.md`](MENTOR_QUESTIONS.md), а также противоречия источников из `data-pack/RULES_PROVENANCE.md` (раздел 5).
- **Уже в движке (набор `demo-0.2`):**
  - страница протокола под каждой причиной на карточке;
  - нормы гемоглобина по триместрам (с. 28): у OB-0001 и OB-0002 одинаковый Hb 107 г/л, но на 22-й неделе это Yashil, а на 28-й — Sariq;
  - «данные устарели» по графику визитов (с. 14, 17, 20);
  - бейджи групп риска по анамнезу: пять шкал (с. 33–41), это профиль, а не зона.
- **Следующий шаг:** остальные правила из `data-pack/` (глюкоза по виду пробы, средняя анемия, ответ на железо) — после ответов ментора.
- **Правовая часть (критерий S4):**
  - только синтетические данные;
  - в алерте номер пациентки, а не имя;
  - для объяснения в Claude уходят только данные оценки, без имени, номера, района и даты рождения (это проверяет тест); заметку для разбора медсестра пишет сама, и интерфейс просит только синтетический текст;
  - ключ API только на сервере;
  - журнал всех действий.

  О локализации данных говорим осторожно. По сообщениям СМИ, поправки от 26.03.2026 ослабили требование хранить данные в стране, но текст закона мы не читали. Формулировка: «в продакшене — серверы в Узбекистане, правовой режим уточним у юриста».

## 5. Короткие ответы на вопросы

- **«Зону ставит ИИ?»** Нет. Зону ставят правила в коде. Claude только читает заметку в черновик формы и объясняет готовую оценку.
- **«Пороги проверены?»** Значения взяты из национального протокола (страницы указаны). Какую зону даёт правило, решила команда, поэтому правила помечены как иллюстративные до проверки врачом.
- **«Данные реальные?»** Нет, полностью синтетические.
- **«А если анализа нет?»** Отсутствие данных не считается нормой: на карточке появляется предупреждение «maʼlumot toʻliq emas».
- **«Чем это лучше Excel?»** Зона пересчитывается при каждом визите, алерт уходит сам, подтверждение и вся цепочка видны в журнале.
