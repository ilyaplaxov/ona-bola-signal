# Вопросы менторам

Рабочий документ команды для менторских сессий и чекпоинта 18 ноября. У каждого вопроса есть контекст: зачем мы спрашиваем, как сейчас сделано и что поменяется от ответа. Так вопрос может задать любой из нас, не зная всей истории проекта.

## Как устроены встречи

- **Менторские сессии:** 18 ноября, 10:00–13:00. Здесь задаём вопросы и получаем советы.
- **Чекпоинт:** 18 ноября, 15:00–17:00.
  - Три отдельные сессии по 10 минут: технический, бизнес- и доменный ментор. Ментор слушает команду один, без двух других.
  - Каждый ставит 1–10 баллов по пяти своим критериям, итог — среднее трёх менторов.
  - В финал проходят 5 лучших команд трека.

| Ментор                            | Что оценивает (критерии из презентации организаторов)                                                                                               | С чем идти                                                         |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| **Soha mentori** (доменный, врач) | S1 актуальность проблемы · S2 глубина понимания сферы · S3 практическое применение · **S4 соответствие законодательству** · S5 масштаб влияния      | Ноутбук с запущенным приложением (RU или UZ), страница **Правила** |
| **Texnik mentor** (технический)   | T1 техническая реализация · T2 готовность кода · T3 инновационность решения · T4 уровень знаний команды · T5 стек технологий                        | Схема архитектуры, репозиторий на GitHub, `npm run e2e`            |
| **Biznes mentor**                 | B1 идея и актуальность проблемы · B2 бизнес-модель и монетизация · B3 конкурентное преимущество · B4 финансовая устойчивость · B5 возможности роста | Цифры по проблеме, кто платит, план пилота                         |

**Как пользоваться файлом:**

- ★ — главные вопросы. Если времени мало, задаём только их.
- Ответ записываем сразу в строку «Ответ» под вопросом: дословно, с именем ментора.
- Вечером переносим решения в [`DECISIONS.md`](DECISIONS.md), а правила — в [`RULES_PROVENANCE.md`](RULES_PROVENANCE.md).
- Если ответ меняет правило, это 15–30 минут работы (раздел «Что поменяется»).

Источники, на которые ссылаемся:

- **АУ** — национальный клинический протокол «Антенатальный уход. Ведение беременных групп риска»;
- **ЖДА** — протокол «Ведение беременных с железодефицитной анемией».

Оба утверждены приказом Минздрава № 180 от 23.06.2025, PDF лежат в `data-pack/`. Номера страниц печатные.

## 2. Технический ментор

Покажите: схему (браузер → API → Risk Engine / Claude → Postgres), репозиторий https://github.com/ilyaplaxov/ona-bola-signal и прогон `npm run e2e` (около 15 секунд, весь сценарий в Chrome).

Что можно сказать о себе:

- зону ставит только детерминированный движок (чистая функция, одинаковый вход даёт одинаковый результат);
- ИИ только читает заметки, объясняет и отвечает на вопросы врача, поле зоны в его ответе отсутствует;
- контракты на Zod общие для фронтенда и бэкенда;
- визит обрабатывается в одной транзакции;
- журнал аудита только дополняется;
- 148 юнит- и интеграционных тестов плюс 4 e2e.
