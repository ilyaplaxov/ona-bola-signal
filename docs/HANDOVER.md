## 2. Запуск за 5 минут

Нужно: Node 22.12+ (подходит 24), npm 10+, запущенный Docker Desktop. Все команды выполнять **из папки `ona-bola-signal`**: из родительской папки npm выдаст `ENOENT ... package.json`.

```bash
cd ona-bola-signal
npm install
npm run db:up      # Postgres 16 в Docker, порт 5433
npm run db:reset   # миграции + демо-данные (24 пациентки, 10 алертов)
npm run dev        # сайт: http://localhost:5173, API: http://localhost:3001
```

Откройте http://localhost:5173/dashboard и выберите роль в правом верхнем углу (на http://localhost:5173 — публичная главная страница, кнопка «Doctor portal» ведёт сюда). Сценарий демо — в [`DEMO_SCRIPT.md`](DEMO_SCRIPT.md).

Проверить весь сценарий одной командой (Chrome, около 15 секунд, база сбрасывается до и после, скриншоты в `docs/demo/`):

```bash
npm run e2e
```

**Включить Claude:** в `backend/.env` записать `AI_ENABLED=true` и `ANTHROPIC_API_KEY=...`, перезапустить `npm run dev`. В логе API появится строка `AI features enabled (...)`, на карточке пациентки — фиолетовые панели «AI». Без ключа или без интернета всё остальное работает, панели ИИ просто скрыты.

| Порт | Что                                                       |
| ---- | --------------------------------------------------------- |
| 5173 | Vite (фронтенд); проксирует `/api` на бэкенд              |
| 3001 | API (переменная `API_PORT`)                               |
| 5433 | Postgres в Docker (`ona_bola` и тестовая `ona_bola_test`) |

Бэкенд читает `API_PORT`, а не `PORT`: превью-раннеры выставляют `PORT` всем процессам, и API однажды занял порт фронтенда. Настройки по умолчанию работают без `.env`; чтобы что-то поменять, скопируйте `backend/.env.example` в `backend/.env`.

Остальные команды (из корня): `npm test`, `npm run e2e`, `npm run typecheck`, `npm run build`, `npm run format`, `npm run db:down`, `npm run db:generate -- --name <имя>`, `npm run db:migrate`.

## 5. Как проходит запрос

**Чтение:** маршрут → `parseInput(схема, …)` (неверный ввод: 400 `VALIDATION_FAILED` с полями) → сервис (Drizzle) → `sendJson(res, схема, данные)`. Ответ сверяется с контрактом: расхождение даёт 500 и лог, тихо разъехаться контракту не дадим. Ошибки всегда имеют вид `{ "error": { "code", "message", "details" } }`.

**Визит (`POST /api/patients/:id/measurements`):** нужна роль (иначе 401). В одной транзакции: блокировка строки пациентки → сохранение показаний → аудит `MEASUREMENTS_ADDED` → Risk Engine по всей истории → запись оценки и текущей зоны → политика алертов → аудит `RISK_ASSESSED` и `ALERT_CREATED`. Повтор с тем же `submissionId` возвращает первый результат (200, `replayed: true`), с тем же id для другой пациентки — 409. Время измерения из будущего — 400.

**Политика алертов** (`services/alert-policy.ts`, одна чистая функция): алерт, когда зона ухудшилась (GREEN → YELLOW, YELLOW → RED, GREEN → RED); первая оценка даёт алерт только если она красная; красная пациентка получает новый алерт, только если сработало новое красное правило; дублей нет, пока висит неподтверждённый алерт. Получатель — роль SPECIALIST.

**Подтверждение (`PATCH /api/alerts/:id/acknowledge`):** только роль получателя (иначе 403 `FORBIDDEN`) и только один раз (иначе 409). Пишется аудит `ALERT_ACKNOWLEDGED`.

**Срок беременности** вводится так, как его определяет врач: по первому дню последней менструации или по УЗИ (дата и срок в неделях и днях). Сервер считает из этого начало беременности и ПДР (+280 дней); ПДР руками больше не вводится. Форма сразу показывает «Сегодня: 14 нед. 0 дн. · ПДР …». Хранится в `patients.pregnancy_start_date` и `dating_method` (миграция 0002); у демо-пациенток метод «по менструации».

**Редактирование (`PATCH /api/patients/:id`, кнопка «Изменить» на карточке):** меняются имя, дата рождения, район, учреждение, врач, срок и анамнез. В аудит `PATIENT_UPDATED` пишутся только названия полей. Если поменялись срок, дата рождения или факторы риска и пациентка уже оценена, движок сразу переоценивает её (возможен новый алерт).

**Регистрация (`POST /api/patients`):** нужна роль. Пациентка создаётся без оценки («Baholanmagan»): первую зону даст первый визит. Повтор номера — 409, дата рождения в будущем или неизвестный врач — 400. Аудит `PATIENT_CREATED` без имени.

**Роль** передаётся заголовком `x-demo-user-id` (переключатель в шапке сайта). Паролей нет и не будет до конца хакатона (бриф, раздел 11).

## 6. Risk Engine

Файлы: `backend/src/risk-engine/`. Вход: даты пациентки, факторы риска и все её измерения. Выход: оценка по контракту.

- **`assess(input, ruleSet, now)`** — чистая функция: не ходит в базу, сеть и часы. Одинаковый вход даёт одинаковый результат и одинаковый `inputHash`. Порядок измерений во входе не важен.
- **Три вида правил:** `THRESHOLD` (условия по последним значениям, поднимает зону), `TREND` (в демо только сообщает), `DATA_QUALITY` (только предупреждает).
- **Зона** — максимальная среди сработавших правил, иначе GREEN. У жёлтой и красной зоны всегда есть причина: это проверяет сама схема.
- **Правило не срабатывает на отсутствующих данных.** Пропуски, устаревшие, будущие и неверные значения превращаются в предупреждения.
- **Причина** содержит `ruleId`, английский текст и `observed` (значения, единицы, время). Интерфейс строит формулировку на выбранном языке из `ruleId` + `observed` (словарь в `frontend/src/i18n/strings.ts`).
- **Демо-правила** — `rules/demo-rules.ts`, набор `demo-0.2`, 25 правил, ILLUSTRATIVE. Все пороги совпадают с национальными протоколами МЗ РУз (приказ № 180 от 23.06.2025, PDF в `data-pack/`): давление 140/90 и 160/110 (с. 34), белок 0,3 г/л (с. 36), глюкоза 5,1 и 7,0 ммоль/л (с. 31), гемоглобин по триместрам 110 / 105 / 110 г/л (с. 28) и ниже 70 г/л (протокол по анемии, с. 13), давность давления и гемоглобина по графику визитов (с. 14, 17, 20), рубец на матке (с. 39). Зоны выбрала команда, врач их не проверял. Подробно — в [`RULES_PROVENANCE.md`](RULES_PROVENANCE.md).
- **Диапазон срока у правила** (`gestationalWeeks`): `{ from, to }` значит `from ≤ неделя < to`. Пороговое правило смотрит неделю на дату самого измерения, поэтому повторная оценка позже не меняет смысла старого анализа; неделя анализа показывается в причине. Правило «данные устарели» смотрит сегодняшнюю неделю. `{ unknown: true }` — только когда срок неизвестен (нет ПДР), со строгим значением, чтобы отсутствие ПДР ничего не прятало.
- **Источник у правила:** `source.ref` (полный текст) и `source.citations` (документ и страницы). Тест проверяет, что страницы из `citations` есть в тексте `ref`.
- **Проверенные правила** — `rules/validated-rules.ts`, пока пустой; включаются `RULE_SET=validated`.

**Как изменить правило:** `demo-rules.ts` (порог, зона, при необходимости `gestationalWeeks` и `citations`) → строка в `RULES_PROVENANCE.md` и подпись на двух языках в `frontend/src/i18n/strings.ts` (`RULE_LABELS`), без них тест упадёт → `npm test` → `npm run db:reset`. Если ментор меняет только зону правила, это одно поле `zone`.

## 6а. Claude (фаза 5)

Файлы:

- `backend/src/services/claude.service.ts` — промпты и вызов;
- `backend/src/services/note-draft.ts` — пересчёт единиц;
- `backend/src/routes/ai.routes.ts` — эндпоинты;
- `frontend/src/components/AiNotePanel.tsx`, `AiExplanation.tsx` — панели в интерфейсе.

- **Включение:** `AI_ENABLED=true` и `ANTHROPIC_API_KEY` в `backend/.env`. Если `AI_ENABLED=true` без ключа, сервер стартует с выключенным ИИ и пишет об этом в лог. `GET /api/health` отдаёт `aiEnabled`; по нему интерфейс показывает или прячет панели.
- **Заметка → форма** (`POST /api/patients/:id/analyze-note`). Claude только переписывает числа и единицы как есть. Пересчёт делает код:
  - гемоглобин: г/дл × 10;
  - белок: мг/дл ÷ 100, мг/л ÷ 1000;
  - глюкоза: мг/дл ÷ 18,016.

  Каждое значение проверяется контрактом. **Значение без единицы не подставляется** (кроме давления, оно всегда в мм рт. ст.): «Hb 11.2» без единицы не превратится в тяжёлую анемию. Ничего не сохраняется: медсестра проверяет форму и сама нажимает «Saqlash va baholash», визит пишется с `source: AI_ASSISTED`, в истории у него метка «AI».

- **Чат для врача** (`POST /api/patients/:id/ai/chat`): карточка «AI yordamchi / ИИ-помощник» на странице пациентки, с готовыми вопросами («Почему эта зона?», «Каких данных не хватает?»).
  - Переписка хранится только в браузере, на сервер каждый раз уходит до 12 последних сообщений.
  - Claude видит обезличенную карту: возраст, срок, факторы риска, группы риска, оценку и историю измерений. Имени, номера, района, учреждения и даты рождения там нет, это проверяет тест.
  - Промпт запрещает ставить или оспаривать зону, ставить диагноз, называть препараты и дозы и добавлять факты, которых нет в карте. На вопросы о лечении ИИ отвечает, что решение за врачом, и отсылает к карточке «Группы риска».
  - Проверено вживую на Haiku 5.5: на просьбу назначить препарат он отказывает.
  - В журнал пишется `AI_CHAT_ANSWERED`: модель, язык и размер обмена, без текста.
- **Объяснение** (`POST /api/patients/:id/risk/explain`). В Claude уходят только данные оценки: зона, причины со значениями, тренды, предупреждения, срок беременности. Имени, номера, района и даты рождения там нет, это проверяет тест. Ответ кэшируется в памяти на пару «оценка + язык». Если оценки ещё нет — 409.
- **Вызов:**
  - модель `claude-opus-5-5` (`CLAUDE_MODEL`), effort `low`;
  - структурированный вывод по схемам из `shared/src/ai.ts`;
  - запасная модель при отказе включена (`fallbacks: "default"`);
  - таймаут 15 с (`CLAUDE_TIMEOUT_MS`) и один повтор.

  Отказ, обрыв по `max_tokens`, не-JSON, ошибка сети или ключа → 503 `AI_UNAVAILABLE`, и интерфейс говорит «AI hozir ishlamayapti…». Зона и алерты от ИИ не зависят никогда.

- **Аудит:** `AI_NOTE_ANALYZED` и `AI_EXPLANATION_GENERATED` с моделью, языком и счётчиками. Текст заметки и ответ модели в журнал не пишутся.
- **Проверка без ключа:** тесты используют подменный клиент SDK и подменный сервис. Первый живой вызов сделайте до чекпоинта (раздел 11).

## 7. База данных

Шесть таблиц (`backend/src/db/schema.ts`): `users`, `patients`, `measurements`, `risk_assessments`, `alerts`, `audit_logs`.

- Срок беременности считается из предполагаемой даты родов при чтении. `current_risk_zone` = null значит «не оценена».
- Один визит — один `submission_id`; уникальный ключ `(submission_id, type)` защищает от дублей.
- `risk_assessments` и `audit_logs` только дополняются. У событий аудита есть `patient_id` и порядковый номер `seq` (миграция 0001): события одной транзакции идут в журнале в том порядке, в каком случились.

**Изменить схему:** правка `schema.ts` → `npm run db:generate -- --name <что_меняем>` → закоммитить новый SQL-файл. Старые миграции не трогать. `npm run db:reset` отказывается стирать нелокальную базу без флага `--allow-remote`.

### Вход

- `POST /api/auth/login {username, password}` ставит httpOnly-cookie `ob_session` на 12 часов. Ответ — `{user, expiresAt}`.
- `GET /api/auth/me` возвращает того же пользователя, без входа — 401 `ACTOR_REQUIRED`. Так фронтенд узнаёт при загрузке, нужен ли экран входа.
- `POST /api/auth/logout` — выход.
- Неверный логин или пароль — 401 `INVALID_CREDENTIALS`.
- Через прокси Vite запросы идут с того же адреса, поэтому cookie уходит сама; `credentials: "include"` не нужен.
- **Переходный режим.** Пока фронтенд шлёт заголовок `x-demo-user-id` (переключатель ролей), всё работает как раньше: `AUTH_DEMO_HEADER` по умолчанию включён. Когда страница входа готова — поставить `AUTH_DEMO_HEADER=false` в `backend/.env`: тогда без входа данные не отдаются (401).
- Права для скрытия кнопок — `can(role, permission)` и `permissionsFor(role)` из `shared`. Сервер проверяет те же права сам и отвечает 403 `FORBIDDEN`.
- При смене пользователя кэш запросов сбрасывается (`session.tsx`): у каждого свой список пациенток.

1. Открывается по ссылке `webPath` из `signal-link` (код в адресе) или пациентка вводит код сама.

### Telegram-бот

Бот **@onabolasignalbot** подключён. Токен лежит только в `backend/.env` (`TELEGRAM_BOT_TOKEN`), в git не попадает и в общий чат не отправляется.

- При запуске `npm run dev` в логе появится `Telegram bot @onabolasignalbot is polling`. Публичный сервер не нужен: бот сам опрашивает Telegram.
- При старте бот сам выставляет описание и меню команд на узбекском (по умолчанию), русском и английском.
- После подключения бот здоровается по имени пациентки и называет её врача («Здравствуйте, Malika Yusupova! Ваш врач: Dr. Aziza Karimova.»). Зону, диагноз и анализы бот не пишет никогда.
- Команды пациентки:
  - `/start КОД` — согласие, потом подключение;
  - `/menu` — кнопки;
  - `/stop` — отключиться и отозвать согласие.
- Без токена бот выключен, остальное работает; `telegramUrl` в ответе будет `null`.
- **Работает, только пока запущен сервер.** Если ноутбук спит или `npm run dev` остановлен, бот не отвечает.
- Бот одновременно может опрашивать только один компьютер. Если запустить проект с тем же токеном у двух человек, второй получит ошибку `409 Conflict`. Токен держит один человек — тот, на чьём ноутбуке идёт демо.

**Выдать код без кнопки в карточке** (пока фронтенд её не сделал):

```bash
npm run signal:link -- OB-DEMO-01
```

Печатает код, ссылку `https://t.me/onabolasignalbot?start=КОД` и ссылку на страницу `/signal`. Код выдаётся от имени врача пациентки и пишется в аудит так же, как из карточки.

## 10. Тесты

## 12. Известные ограничения

- Демо-правила и шкалы групп риска не проверены врачом: значения взяты из национальных протоколов, а зоны выбрала команда. Из `data-pack/` встроены пункты «к чекпоинту» (раздел 6б); глюкоза по виду пробы и новые виды правил ещё нет.
- Группы риска считаются при чтении карточки и в журнал аудита не пишутся (это не зона). Форма регистрации и редактирования спрашивает число родов, ИМТ и 15 самых частых факторов анамнеза; остальные коды шкал вводятся только через API. Меры из протокола (например, аспирин) на карточке подписаны «по протоколу, иллюстративно, решение за врачом».
- Подписи протоколов и шкал на узбекском (`SOURCE_LABELS`, `RISK_FACTOR_LABELS`, раздел `riskGroups` в `strings.ts`) тоже писал не носитель.
- Claude проверен вживую 18 ноября утром на `claude-haiku-5-5` (ключ в `backend/.env`): объяснение и разбор заметки на узбекском и русском, ответ около 4 секунд. Для Haiku 5.5 у Anthropic нет запасной модели при отказе, поэтому строка лога «refusal fallback on» на ней ничего не меняет.
- Правило преэклампсии не проверяет срок 20+ недель (ошибается в сторону тревоги). Комбинированные правила берут последнее значение каждого показателя, даже если анализы сделаны в разные недели. Глюкоза трактуется как значение натощак. Возраст пока ни в одном правиле.
- Узбекские тексты интерфейса и предупреждения ИИ-черновика написаны не носителем языка, их нужно проверить.
- `npm audit`: в зависимостях приложения уязвимостей нет; 10 находок в инструментах разработки (vite, vitest, drizzle-kit). Они работают только локально, поэтому не обновлялись.
- Направление тренда на экране определяется по английскому тексту находки (`fell`): если поменять этот текст в движке, поправьте `RiskExplanation.tsx`.
- Входящие обновляются опросом раз в 5 секунд, а не push-уведомлением. Telegram и SMS не подключены (бриф, раздел 5.5).
- Авторизации нет, только демо-заголовок роли. Любой пользователь с ролью SPECIALIST может подтвердить любой алерт.
- Два PDF с протоколами лежат в `data-pack/` вместе с пакетом данных второго участника (`data-pack/README.md`). Папка исключена из Prettier и хранится как прислана.

## 13. Частые проблемы

| Симптом                                             | Причина и решение                                                                                                      |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `npm error enoent Could not read package.json`      | Команда запущена не из папки `ona-bola-signal`                                                                         |
| `Port 5173 is in use` или API не стартует           | Уже запущен другой `npm run dev`; остановите его                                                                       |
| Красная точка в шапке, «Maʼlumotni yuklab boʻlmadi» | API или база не отвечают: Docker Desktop, `npm run db:up`, `npm run dev`                                               |
| Кнопка «Saqlash va baholash» неактивна              | Не выбрана роль в шапке                                                                                                |
| Кнопка «Tasdiqlash» неактивна                       | Подтверждать может только роль Mutaxassis                                                                              |
| Ошибки `relation ... does not exist` в логе API     | База пустая: `npm run db:reset`                                                                                        |
| Интеграционные тесты «skipped»                      | Тестовая база недоступна: запустите Docker и `npm run db:up`                                                           |
| `Refusing to reset ...: it is not a local database` | Защита от стирания общей базы; флаг `--allow-remote` только если точно нужно                                           |
| Не видно панелей «AI»                               | ИИ выключен: `AI_ENABLED=true` и ключ в `backend/.env`, перезапуск `npm run dev`                                       |
| «AI hozir ishlamayapti…»                            | Нет интернета, неверный ключ или таймаут; причина в логе API (`reason`)                                                |
| `npm run e2e` падает на запуске браузера            | Нужен установленный Google Chrome; иначе `npx playwright install chromium` и убрать `channel` в `playwright.config.ts` |
