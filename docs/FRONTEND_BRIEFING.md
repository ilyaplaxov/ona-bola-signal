## 1. Как отправить работу в git

### 1.1. Сначала сохранить свою работу

В папке `ona-bola-signal`:

```bash
git status
```

Если есть изменения — закоммитить **только свои файлы**:

```bash
git add frontend e2e
```

```bash
git commit -m "Коротко: что сделано"
```

Не добавлять:

- `backend/.env` и любые файлы с ключами и токенами;
- материалы хакатона из корня (pdf, pptx, бриф);
- `telegram_bot.md`.

`git add -A` не использовать: он заберёт лишнее.

### 1.2. Забрать изменения бэкенда

```bash
git pull --rebase origin main
```

Если git сообщил о конфликте — смотреть раздел 1.3. Если нет — сразу переходить к 1.4.

### 1.3. Конфликты: какие твои файлы я поменял и зачем

Без этих правок `main` не собирался или не проходил тесты после изменений бэкенда. При конфликте оставляй **и свои изменения, и мои**.

| Файл                           | Что я поменял                                                                                                                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `frontend/src/i18n/strings.ts` | В раздел `audit` всех трёх языков добавил подписи новых событий журнала (`USER_LOGGED_IN`, `REFERRAL_CREATED`, `ATTACHMENT_UPLOADED`, `SIGNAL_RECEIVED`, `SIGNAL_UNLINKED`, `DIMED_SENT` и другие). Без них не проходит `typecheck`. |
| `frontend/src/app/session.tsx` | При смене пользователя сбрасывается кэш запросов: `queryClient.invalidateQueries()`. Теперь у каждого пользователя свой список пациенток, иначе после переключения видны чужие данные.                                               |
| `e2e/demo-flow.spec.ts`        | Регистрирует пациентку врач (Aziza Karimova), а не медсестра: по матрице прав медсестра регистрировать не может. Счётчик алертов у специалиста сравнивается с его собственным: медсестра видит только свой район.                    |

Как разрешить конфликт:

1. Открыть файл и найти блоки между `<<<<<<<`, `=======` и `>>>>>>>`.
2. Оставить обе версии и удалить маркеры.
3. Выполнить:

```bash
git add <файл>
```

```bash
git rebase --continue
```

Если запутался:

```bash
git rebase --abort
```

Эта команда вернёт всё как было до `pull`, ничего не потеряется. Потом напиши Участнику 1.

### 1.4. После pull — один раз

```bash
npm install
```

```bash
npm run db:reset
```

- `npm install` нужен из-за новой зависимости бэкенда (multer).
- `npm run db:reset` применяет миграции 0003–0007 и заводит демо-аккаунты с паролями.

### 1.5. Перед каждым пушем

```bash
npm run format && npm run typecheck && npm test
```

```bash
npm run e2e
```

Если всё зелёное:

```bash
git push origin HEAD:main
```

Если push отклонён (кто-то успел запушить раньше) — повторить `git pull --rebase origin main`, проверки и push.

### 1.6. Правила

- Твои папки — `frontend/` и `e2e/`. Если нужно поменять `shared/` или `backend/`, напиши Участнику 1: он владеет контрактами и миграциями.
- Пушить небольшими кусками и часто, чтобы конфликты были маленькими.
- Никогда не использовать `git push --force`.
- Коммит без проверок из 1.5 не пушить: на `main` работают все трое.

**Переходный режим.** Старый переключатель ролей (заголовок `x-demo-user-id`) пока работает, поэтому текущий фронтенд не сломан. Когда страница входа будет готова, в `backend/.env` ставится `AUTH_DEMO_HEADER=false`, и без входа API отвечает 401.

### Права

Сервер проверяет права сам и отвечает 403 `FORBIDDEN`. Та же таблица есть в `shared`:

- `can(role, permission)`;
- `permissionsFor(role)`.

Используй их, чтобы **скрывать кнопки**, которые роли недоступны: регистрация, направление, загрузка, подтверждение алерта, выдача кода.

### P0 — без этого на финал не выходим

1. **Дизайн** (если ещё не сделан):
   - базовый шрифт 18 px;
   - спокойная палитра;
   - крупнее кнопки и поля;
   - контраст не ниже WCAG AA;
   - цвета зон должны оставаться различимыми.
2. **Вход:**
   - страница `/login`: логин и пароль, ошибка `INVALID_CREDENTIALS` («неверный логин или пароль»);
   - на ней же подсказка с демо-аккаунтами из `/api/auth/demo-accounts`;
   - при загрузке приложения — `GET /api/auth/me`; ответ 401 → на `/login`;

   - при входе и выходе — `queryClient.clear()`;
   - из `services/api.ts` убрать заголовок `x-demo-user-id`.
   - Публичные страницы `/` и `/signal` работают без входа.
3. **Профиль врача и «Мои пациентки»:**
   - страница профиля с данными из `/api/auth/me`;
   - в реестре — переключатель «Все в районе / Мои» (`assigned=me`).
4. **Карточка пациентки — вкладки «Обзор / Визиты / Документы / Направления».** На «Обзоре» всё, что есть сейчас: зона, причины, ИИ-объяснение, чат.
5. **Документы:**
   - загрузка кнопкой и перетаскиванием, с выбором типа (УЗИ / заключение специалиста / анализы / МРТ / другое) и описанием;
   - список файлов;
   - просмотр: PDF — `<iframe src="/api/attachments/:id/file">`, картинки — `<img>`, МРТ (DICOM) — только ссылка на скачивание.
6. **Направления:**
   - форма «Направить к специалисту»: специальность (`Specialty` из `shared`), причина, срочность;
   - у консультанта — «Входящие направления» с кнопками «Принять» и «Дать заключение» (текст и выбор файлов пациентки);
   - у врача — «Закрыть» после заключения и «Отменить» до него;
   - статусы — значками.

### P1 — делаем после P0

7. **Сигналы пациенток (врач):**
   - в карточке кнопка «Подключить Telegram»: показать код, ссылку `telegramUrl` и `webPath`; QR — если успеешь;
   - в карточке статус «подключена / нет» (`signalLink`);
   - сигналы в алертах или отдельной вкладке, с пометкой «от пациентки» и кнопками «Связались», «Вызвана на приём», «Направлена в стационар»;
   - `escalated: true` — выделить: прошло 30 минут без реакции;
   - на дашборде — счётчик `newSignals`;
   - для демо обновлять список сигналов каждые 5–10 секунд (`refetchInterval`): на сцене сигнал должен появиться у врача без перезагрузки.
8. **Страница пациентки `/signal`:**
   - **без входа и без `Layout`**, как `HomePage`; удобна с телефона, крупные кнопки;
   - код берётся из адреса (`?code=`) или вводится вручную;
   - согласие (`SIGNAL_TEXTS[lang].consent` и кнопка `agree`) → `redeem` → токен сохраняется в `localStorage` (чтение и запись — в `try/catch`), код убирается из адреса через `history.replaceState`;
   - кнопки в порядке `SIGNAL_BUTTON_ORDER`, подписи из `SIGNAL_TEXTS[lang].kinds`;
   - после нажатия — крупно текст `SIGNAL_TEXTS[lang].instructions[instruction]`;
   - все тексты уже есть в `shared` на uz, ru и en — те же, что в боте.
9. **ИИ читает документ:**
   - у файла PDF или фото кнопка «Прочитать (ИИ)» → `POST /api/attachments/:id/analyze`;
   - найденные значения заполняют форму визита так же, как сейчас работает заполнение из заметки (`AiNotePanel`);
   - если пришёл `dating` (срок по УЗИ), предложить «Записать срок в карту» → `PATCH /api/patients/:id` с `{ dating }`;
   - ничего не сохраняется без нажатия врача;
   - пометить значком `AiBadge`.
10. **DIMED:**
    - у файла — значок из `dimedStatus`: «отправлено в DIMED» или «ожидает»;
    - у визитов — статус из `GET /api/patients/:id/dimed` (запись с `recordType: "VISIT"`, `recordId` = `submissionId` визита).

## 4. Подводные камни

- **Загрузка файла.** `requestJson` в `services/api.ts` ставит `Content-Type: application/json`, если есть тело. Для `FormData` заголовок `Content-Type` ставить **нельзя**: браузер сам выставит `multipart/form-data` с разделителем. Сделай отдельную функцию загрузки или пропускай заголовок для `FormData`.

  ```ts
  const form = new FormData();
  form.append("kind", "ULTRASOUND");
  form.append("file", file);
  await fetch(`/api/patients/${id}/attachments`, { method: "POST", body: form });
  ```

  Ответы на ошибки:
  - 413 — файл больше 10 МБ;
  - 415 — не PDF, JPG, PNG или DICOM (тип проверяется по содержимому, а не по расширению).

- **Cookie.** Через прокси Vite запросы идут с того же адреса, поэтому cookie уходит сама. `credentials: "include"` не нужен.
- **Коды ошибок** (`ApiError.code`):
  - `ACTOR_REQUIRED` (401) — не вошёл;
  - `INVALID_CREDENTIALS` — неверный пароль;
  - `FORBIDDEN` (403) — нет прав;
  - `RATE_LIMITED` (429) — слишком много попыток;
  - `AI_UNAVAILABLE` (503) — ИИ выключен или не ответил.
- **Консультант** (`yusupova`, `nazarov`) видит пустой реестр, пока к нему нет направления. Это не ошибка, но нужен понятный пустой экран: «Нет пациенток с направлением к вам».
- **ИИ у тебя.** Без ключа Claude в `backend/.env` ИИ-кнопки скрыты (`aiEnabled: false` в `/api/health`). Ключ попроси у Участника 1 лично, не в общем чате. Можно проверять ИИ на его ноутбуке.
- **Бот.** Токен Telegram **не ставь себе**: бот с одним токеном одновременно работает только на одном компьютере, второй получит `409 Conflict`. Для проверки страницы `/signal` бот не нужен: код даёт `npm run signal:link -- OB-DEMO-01`.
- **e2e** использует уже запущенный `npm run dev`. Если во время прогона меняешь бэкенд, сервер перезапускается, и тест может упасть случайно. Прогоняй e2e, когда ничего не редактируешь.
- **Без реальных данных.** Только синтетические файлы и вымышленные имена. ИИ никогда не ставит и не меняет зону: всё, что он предлагает, подтверждает врач.
