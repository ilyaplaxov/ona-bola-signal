# Ona-Bola Signal — пакет данных для Risk Engine

Собрано 17.11.2026 для человека 2 (раздел B плана): источники правил, нормы, формулы, синтетические пациентки и цифры для питча.

## Вердикт по двум PDF

Оба PDF — **действующие национальные клинические протоколы Минздрава Узбекистана**: приказ №180 от 23.06.2025, разработчик РСНПМЦЗМиР, внешняя экспертиза ВОЗ, пересмотр в 2030 году. Это ровно то, что план называет приоритетным источником (раздел B.1: «национальный протокол или приказ Минздрава»). ВОЗ теперь нужна только для сравнения.

Что они закрывают:

| Нужно по плану | Есть в протоколах |
|---|---|
| Пороги АД и белка (гипертензия, ПЭ) | АУ с.33–36: 140/90, 160/110, признаки тяжёлой ПЭ, срочная госпитализация |
| Пороги Hb (анемия) | АУ с.20, с.28; весь протокол ЖДА: степени, лечение, критерий ответа +10 г/л за 2 нед |
| Пороги глюкозы (ГСД) | АУ с.20–21, с.30–32, с.53: 5,1 / 7,0 / ПГТТ 10,0 / 8,5 / 11,1, HbA1c 6,5 |
| Шкала факторов риска | АУ с.33–41: пять шкал — ПЭ, ГСД, ВТЭО в баллах, ПРК, ЗРП |
| График визитов для правила «данные устарели» | АУ с.13–14: 8 визитов (до 12, 18–20, 26, 30, 34, 36, 38, 40 нед), анализы — с.19–21, сводная таблица — с.50–51 |
| Единицы районных лабораторий | Протоколы пишут в г/л, ммоль/л, мм рт. ст. — совпадает с допущениями плана (у ментора всё равно уточнить) |

Бонусом в протоколах есть:
- 13 тревожных признаков (с.30);
- 17 показаний к госпитализации (с.42);
- 18 критериев качества помощи (с.42–44);
- шкала депрессии EPDS (с.57);
- алгоритм ведения при резус-отрицательной крови (с.56).

### Что нужно добавить в контракты (только новые поля)

- `gestationalWeeks?: { from?, to? }` в правиле — без него не работает норма Hb по триместрам.
- `context` у измерения глюкозы (`FASTING`, `OGTT_1H`, `OGTT_2H`, `RANDOM`) — или отдельные типы.
- Типы правил `all` (АД + белок = ПЭ), `response` (нет прироста Hb) и `windowDays` у тренда. Если не хотите их добавлять, уберите соответствующие правила: остальные работают на форме из плана.
- Узбекские строки в `reason.uz` написаны не носителем — покажите их кому-то из команды.

### Синтетика (`synthetic-seed.json`)

Распределение:
- 15 пациенток в зелёной зоне, одна из них с пропущенными визитами («Green · неполные данные»);
- 6 в жёлтой: лёгкая анемия ×2, средняя анемия без ответа на лечение, ГСД ×2, гестационная АГ;
- 2 в красной: тяжёлая ПЭ (165/108 + белок 1,0) и тяжёлая анемия (Hb 66);
- 2 без данных.

Демо-пациентка `OB-0025`:
- 40 лет, первородящая, поэтому высокий риск ПЭ;
- ровная зелёная история на 10, 19, 26 и 30 неделях;
- на демо вносим 164/112 и белок 0,6 г/л → RED: BP-SEV-SYS, BP-SEV-DIA, PE-BP-PROT;
- запасной вариант: 146/92 → YELLOW.

Как устроены ожидаемые значения:
- У каждой пациентки есть `expectedZone`, `expectedRuleIds` и `riskGroups`. Это готовые ожидания для тестов движка.
- Динамические правила здесь не вычисляются — они описаны текстом в `expectedDynamicRules`.
- Данные детерминированы: тот же seed PRNG даёт тот же файл. Ни одна запись не взята у реальных людей.

### Право (критерий S4) — предположение плана устарело

План исходит из того, что все персональные данные граждан хранятся только в Узбекистане (ст. 27-1, с 2021 года). По [spot.uz, 27.03.2026](https://www.spot.uz/ru/2026/03/27/personal-data/) и [04.08.2026](https://www.spot.uz/ru/2026/08/04/personal-data-abroad/) это изменилось:
- **26.03.2026** подписаны поправки. Обязательная локализация осталась только для биометрических и генетических данных и данных абонентов телеком-операторов.
- Остальные данные можно хранить за рубежом при одном из условий: адекватная страна, типовые договорные условия или корпоративные правила, международный стандарт из утверждённого списка.
- **29.07.2026** утверждён список из 49 «адекватных» стран, среди них США и Германия ([lex.uz/ru/docs/8369688](https://lex.uz/ru/docs/8369688)).
- При утечке во время трансграничной передачи — уведомление за 24 ч, детали за 72 ч.

Это пересказ СМИ, текст закона мы не читали. Медицинские данные в статьях не упомянуты, врачебная тайна и закон об охране здоровья тоже не проверены. Для питча безопасная формулировка: «синтетические данные; прод — на серверах в Узбекистане; в Claude уходят только обезличенные значения без ФИО и даты рождения (раздел 9 плана); правовой режим уточним у юриста». Закон «О персональных данных» — ЗРУ-547 от 02.07.2019, редакцию проверить на lex.uz.

## Идеи — что даст очки

**К чекпоинту (почти бесплатно, уже есть данные):**
1. **Ссылка на протокол в каждой причине.** «Manba: НКП Антенатальный уход, 36-bet» в `ReasonsPanel`. Это главный аргумент для доменного ментора (S1–S3): движок не выдумывает, а цитирует приказ №180. Строка уже лежит в `source.ref`.
2. **Нормы Hb по триместрам.** Один и тот же Hb 107 даёт разную зону на 20-й и 30-й неделе. Наглядно показывает клиническую корректность.
3. **Бейджи групп риска** на карточке (`risk-scales.ts`): «Высокий риск ПЭ → аспирин 150 мг, самоконтроль АД». Работают на анамнезе, новых измерений не требуют.
4. **«Данные устарели» по графику протокола**: «нет ОАК 26 нед», «нет ПГТТ 26–28 нед». Закрывает требование брифа «отсутствие данных ≠ норма».

**После чекпоинта и в roadmap:**
5. **Дашборд критериев качества** по учреждению (18 критериев, АУ с.42–44): «АД измерено при каждом визите — 92 %». Это KPI для районного управления, то есть ответ бизнес-ментору на вопрос «кто платит».
6. **Чек-лист тревожных признаков** в форме измерения (13 пунктов, АУ с.30) → RED. Те же пункты — памятка пациентке на узбекском.
7. **Графики с линиями норм:** Hb (110 / 105 / 90 / 70), АД (140/90, 160/110), глюкоза (5,1 / 7,0), гравидограмма с центилями INTERGROWTH, коридор прибавки веса.
8. **Claude «объясни со ссылкой»:** retrieval по тексту двух протоколов, ответ цитирует страницу. Зону Claude по-прежнему не ставит.
9. **EPDS** — 10 вопросов о настроении (АУ с.57).
10. **Резус-отрицательные** — напоминание об анти-D в 28–30 нед (АУ с.56).
11. **Скрининг домашнего насилия** (АУ с.52) — только с осторожностью.
12. **Новорождённые и выписка (проблемы #10, #11)** — стандарты INTERGROWTH для новорождённых.

## Что не проверено

- Зоны — решение команды, клинической валидации нет. Противоречия источников — раздел 5 `RULES_PROVENANCE.md`.
- `expectedZone` в синтетике посчитан эталонной функцией: только пороги и комбинации, последнее значение каждого показателя. Правила «устарело» проверены тестом. Трендовые правила (TR-*) на синтетике не прогонялись.
- Статистика взята частично из СМИ, без открытия первоисточника (отмечено в таблице). Текст закона о персональных данных не читали.
- Узбекские формулировки не проверены носителем.
